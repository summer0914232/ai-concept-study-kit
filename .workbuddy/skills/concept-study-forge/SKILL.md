# concept-study-forge · 概念学习资料生成器

## 0. 定位

输入一个概念名，输出一份**能拿去讲给别人听**的学习资料单页。
硬性要求：资料里每一条对外事实都必须能点开验证，每一个观点都必须标明是「事实」还是「我的判断」。

这个 Skill 不是三个概念的一次性提示词。验收标准是：**随便给一个新概念名，不改本文件就能产出符合第 4 节八节结构的资料。**

---

## 1. 适用场景

### 该用

| 场景 | 例子 |
| --- | --- |
| 学一个新概念，想要结构化笔记 | 「帮我搞懂 KV Cache」 |
| 概念学过但讲不清楚，要补自己的理解 | 「RAG 我知道大概，但说不出边界，帮我整理」 |
| 准备课程汇报 / 组会分享的概念页 | 「为 LoRA 生成一份学习资料，要能放到 PPT 里讲」 |
| 分辨一对容易混的概念 | 「Agent 和 Workflow 到底差在哪」 |
| 建立个人知识库的概念词条 | 「把『上下文工程』收进我的学习资料库」 |

### 不该用

- 要的是可直接运行的工程代码 —— 换工程类 Skill
- 要的是论文全文精读与实验复现 —— 换文献精读类流程
- 概念本身无公开可核查来源（如内部未公开项目）—— 改用访谈式提问，不要硬凑来源
- 用户只想要一句话定义 —— 直接回答，不要启动完整流程

## 2. 输入信息

| 字段 | 必填 | 说明 | 缺省值 |
| --- | --- | --- | --- |
| `concept` | ✅ | 概念名，中文或英文 | 无，缺失则必须反问 |
| `background` | ⬜ | 学习者的知识背景 | 「具备基础计算机素养的大学生」 |
| `depth` | ⬜ | `速览` / `标准` / `深入` | `标准` |
| `language` | ⬜ | 输出语言 | 简体中文（术语保留英文原名） |
| `output_dir` | ⬜ | 输出目录 | `learning-materials/` |
| `focus` | ⬜ | 特别想搞清楚的角度 | 无 |
| `taboo_sources` | ⬜ | 明确不想引用的来源类型 | 无 |

`depth` 档位差异：

- `速览`：机制部分只留一张对照表，来源 ≥3 条，篇幅控制在半页
- `标准`：完整八节，机制部分含一张流程图或对照表
- `深入`：额外增加「关键变量 / 参数怎么调」「该领域的开放争议」两小节，来源 ≥5 条

**输入不全时的处理**：只反问缺失的**必填**项，其余按缺省值直接开工，不要反复追问。

## 3. 生成步骤（S1–S8）

### S1 定位边界（先想清楚再检索）

1. 写一句话定义，≤40 字，禁止出现概念名本身（避免循环定义）
2. 写出**三个「它不是什么」**——这比定义更能暴露理解漏洞
3. 确定所属学科 + 上/下位概念 + 最容易被混淆的邻居概念

### S2 检索取证（先验证，再引用）

1. 按第 5 节的来源分级，找出 ≥3 条候选来源，其中一手来源 ≥1 条
2. **逐条验活**，只保留返回 `200` 或有效跳转（301/302 且最终可达）的链接：

   ```bash
   curl -s -o /dev/null -L -w "%{http_code}  %{url_effective}\n" --max-time 20 "<URL>"
   ```

   网络受限（代理拦截、超时）导致无法验证的链接，**一律弃用**，不要「先写着以后再查」
3. 记录每条来源的：类型、我引用了它的什么、可信度评级、访问日期

### S3 搭骨架

按第 4 节建立八节标题，顺序不可变。缺内容的节先留占位，不要删节。

### S4 写「我的理解」（本 Skill 的核心，也是最容易被 AI 写砸的一节）

必须同时包含三样东西：

1. **一个类比**：来自日常生活或其他学科，且要说明这个类比在哪一步会失效
2. **一次认知修正**：句式固定为「我原来以为……，查证后发现……」
3. **一句可被反驳的判断**：明确表达立场（例：「我认为 X 的价值被高估了，因为……」）。只做中立复述等于没写

### S5 拆机制

- 拆出**组成要素**（3–6 个）、**运行流程**（有序步骤）、**关键变量**（改了会明显影响结果的量）
- 必须配一张图（Mermaid 流程图）或一张对照表，纯文字不允许
- 数字、参数、年份必须来自 S2 已验证的来源，或明确标注为「示意值」

### S6 写场景

只写一个场景，但要写全四要素：**输入 → 过程 → 输出 → 失败会怎样**。
「失败会怎样」最常被省略，也最能检验是否真懂。

### S7 写边界

- ≥3 条易混淆点，用 `A vs B` 对照表呈现，每行给出「怎么区分」的可操作判据
- ≥2 条使用边界 / 失效条件，写清「什么时候不该用它」

### S8 自检

按第 6 节红线表逐条打勾。任何一条不过 → 回到对应步骤返工。
**不允许带病交付**：自检清单不是装饰，是发布闸门。

---

## 4. 输出结构（固定八节，顺序不可变）

1. **一句话定义** —— ≤40 字，不含概念名
2. **我的理解** —— 类比 + 认知修正 + 一句可被反驳的判断
3. **核心机制** —— 组成要素 / 运行流程 / 关键变量（含图或表）
4. **一个具体应用场景** —— 输入 → 过程 → 输出 → 失败代价
5. **容易混淆的问题与使用边界** —— ≥3 条混淆点对照 + ≥2 条失效条件
6. **最小实践** —— 15 分钟内可完成的验证动作，给出可复制的命令或步骤
7. **可核查来源** —— 表格：类型 / 链接 / 我引用了它的什么 / 可信度 / 访问日期
8. **自检清单** —— 逐条对应第 6 节红线，每条标注 ✅ / ⚠️ 与处理方式

输出为**自包含单页 HTML**（样式内联，双击即可打开），文件名用英文 kebab-case。
中文概念名在页面副标题给出，文件名仍用英文。

若在 Markdown 环境（如 GitHub）查看，同时导出一份同名 `.md`；Mermaid 图在 `.md` 中原生渲染，
在 `.html` 中通过 CDN 渲染，且必须附文字版兜底说明。

## 5. 资料来源要求

### 分级

| 级别 | 包含 | 用法 |
| --- | --- | --- |
| **一手** | 原始论文（arXiv / ACL / IEEE）、官方文档、协议规范、发布方工程博客 | 必须 ≥1 条；用于支撑定义、机制、数字 |
| **二手** | 综述、教科书、权威教程、领域专家的系统性博客 | 用于交叉验证与通俗解释 |
| **参考** | 百科类条目、行业报告、问答社区高赞回答 | 只能用于背景与术语，不能作为唯一依据 |
| **禁用** | 无署名营销文、SEO 内容农场、无法打开的链接、AI 生成的「看起来像」的引用 | 出现即作废 |

### 硬性规则

1. 数量 ≥3，一手 ≥1，覆盖 ≥2 个不同机构/作者
2. **生成前逐条 curl 验活**，只保留可达链接
3. 严禁编造 URL、DOI、论文标题、数字。宁可少引，不可假引
4. 每条来源必须写清「我从这条来源取了什么」，避免"挂羊头"式引用
5. 正文用显式标签区分三种陈述：
   - `[事实]` —— 有来源支撑，可核查
   - `[推断]` —— 由多条事实推得，必须写明推理链
   - `[我的判断]` —— 个人观点，必须给出理由，并允许被反驳
6. 时效性：AI 领域概念优先引用近 3 年来源；引用早期经典（如 2017 年 Transformer）时注明「奠基性文献」

## 6. 自检要求（红线，逐条打勾）

| # | 红线 | 不过时回到 |
| --- | --- | --- |
| 1 | 边界清晰：既写了「是」，也写了「不是」 | S1 |
| 2 | 全部外链生成当日验证可访问 | S2 |
| 3 | 无编造的 URL / 数字 / 论文标题 | S2 |
| 4 | 来源 ≥3，含 ≥1 条一手来源，覆盖 ≥2 个机构 | S2 |
| 5 | 至少 1 个具体场景，且写清了失败后果 | S6 |
| 6 | ≥3 条易混淆点、≥2 条使用边界 | S7 |
| 7 | 「我的理解」里存在一句可被反驳的判断，不是流水账复述 | S4 |
| 8 | `[事实]` / `[推断]` / `[我的判断]` 三类陈述已显式区分 | S5 |
| 9 | 术语首次出现有解释，未把行话当常识 | 全文 |
| 10 | 页面浏览器可直开，图表有文字兜底 | S5 |
| 11 | 通读一遍能讲给同背景的同学听懂 | 全文 |

任一红线不过 → 返工，不交付。自检清单写入资料第 8 节，供读者复核。

## 9. 最低实现要求

产出页面时必须：

1. 复制 `templates/lesson-template.html` 的样式骨架，保证多份资料视觉一致
2. 第 3 节的图优先用 Mermaid（`classDiagram` / `flowchart`），并在图下方给出等价的文字说明
3. 第 7 节来源表格的每一格都要填，不能留空

## 10. 复用到新概念的验收标准（本 Skill 自己也要过这一关）

给出任意一个新概念名（不在本文件任何示例中出现过的），在**不修改 SKILL.md** 的前提下，
能直接产出符合第 4 节八节结构、通过第 6 节十一条红线的资料 —— 这才说明它是真可复用。
若发现必须改 SKILL.md 才能跑通，说明流程里混入了针对特定概念的硬编码，应当剔除。
